# Wave O2B — reutilización y límites de autoridad

Esta revisión distingue las autoridades existentes que O2B consume de los registros que la ola crea. La ruta operativa canónica de Procurement usa un **Project Workspace** activo, no un identificador del proyecto legacy. No hay importación histórica ni doble escritura entre dominios. Se mantiene el límite de [ADR 94: Procurement vs Commitments](../../94-adr-operational-procurement-vs-commitments-boundary.md): el hecho operacional de compra no constituye por sí solo una obligación financiera neta.

La migración [0077](../../../backend/alembic/versions/20261111_0077_procurement_foundation.py) añade estas 27 tablas operativas y protecciones PostgreSQL sin conversión de datos legacy. También protege las revisiones publicadas del nuevo tipo de perfil en `admin_configurations`. La migración rechaza reversión si se han creado registros O2B. El CLI de aprovisionamiento exige un administrador organizacional existente y registra el motivo; no es parte del arranque normal ni se usa para asignar usuarios a roles. Para consultar su interfaz sin ejecutar el aprovisionamiento: `python -m app.modules.procurement_foundation.provision --help` desde `backend`.

## Evidencia focal de sourcing

[`test_procurement_sourcing_policy.py`](../../../backend/tests/test_procurement_sourcing_policy.py) comprueba en SQLite aislado la tabla de transiciones, catálogos estrictos, aprovisionamiento auditado, separación de funciones en revisiones de PO, protección de versión, repetición idempotente, alcance del proyecto y el límite impuesto por cantidades físicamente reservadas. Esta suite no certifica los disparadores de PostgreSQL. El recorrido operacional integrado y los controles de preservación se verifican por separado.
